## 0. 결론

아래 확률표를 기준으로 모든 상자를 즉시 개봉한다고 가정하면 28일 기대 획득량은 다음과 같다.

| 키트 | 28일 기대 획득량 | 주간 기대 획득량 |
| --- | ---: | ---: |
| 파랑 키트 | 473.912개 | 118.478개/주 |
| 보라 키트 | 55.808개 | 13.952개/주 |
| 노랑 키트 | 24.736개 | 6.184개/주 |

이 값은 현재 활성 수급 예측 `supply-2026-08-21-v1`과 일치한다. 제품 코드의 정본은
`shared/supplyForecasts.json`이며, TypeScript와 Rust 상수는 코드 생성으로 만들어진다.

```ts
{
  "id": "supply-2026-08-21-v1",
  "basisDays": 28,
  "effectiveFrom": "2026-08-21",
  "expectedGain": { "blue": 473.912, "purple": 55.808, "yellow": 24.736 }
}
```

향후 보상 주기가 바뀌면 기존 항목의 값을 수정하지 않는다. 새 ID와 새 수급량을 목록에
추가하고 `activeForecastId`만 새 ID로 변경한 뒤 `npm run generate:supply-forecast`를
실행한다. 이 불변 규칙 덕분에 D1 통계에 저장된 `forecast_id`만으로도 당시 계산에 사용한
수급량을 레지스트리에서 정확히 복원할 수 있다. 진단 v1~v6처럼 ID가 없던 과거 통계는
`legacy-unversioned`로 구분하며 특정 수급량을 임의로 추정하지 않는다.

## 7. 검산용 코드

```js
const purpleBox = { blue: 3 * 0.8, purple: 1 * 0.2, yellow: 0 };
const yellowBox = { blue: 5 * 0.7, purple: 2 * 0.2, yellow: 2 * 0.1 };

const add = (...rows) =>
  rows.reduce(
    (sum, row) => ({
      blue: sum.blue + row.blue,
      purple: sum.purple + row.purple,
      yellow: sum.yellow + row.yellow,
    }),
    { blue: 0, purple: 0, yellow: 0 },
  );

const scale = (row, n) => ({
  blue: row.blue * n,
  purple: row.purple * n,
  yellow: row.yellow * n,
});

const daily = add(
  { blue: 2 * 0.15, purple: 0, yellow: 0 },
  { blue: 3 * 0.15, purple: 0, yellow: 0 },
  { blue: 0, purple: 2 * 0.06, yellow: 0 },
  { blue: 0, purple: 3 * 0.03, yellow: 0 },
  { blue: 0, purple: 0, yellow: 1 * 0.04 },
  { blue: 0, purple: 0, yellow: 2 * 0.02 },
  scale(purpleBox, 1 * 0.15),
  scale(purpleBox, 2 * 0.08),
  scale(yellowBox, 1 * 0.08),
  scale(yellowBox, 2 * 0.04),
);

const daily28 = scale(daily, 28);
const solo28 = add(scale(purpleBox, 16), scale(yellowBox, 68));
const coop28 = scale(yellowBox, 40);
const total28 = add(daily28, solo28, coop28);

console.log({ daily, daily28, solo28, coop28, total28 });
```

## 8. 주의

이 문서는 기대 획득량 산출 근거만 보존한다. 실제 추천 정책은 이 값을 그대로 “획득 보장량”으로
보지 않고, `supply` 비용식의 가용량 분모에 다음 형태로 반영한다.

```text
availability[kit] = currentStock[kit] + 0.75 * EXPECTED_28_DAY_GAIN[kit]
```

즉 현재 solver는 28일 기대값 전체가 아니라 21일분 기대 획득량을 수급 완충분으로 본다.
제품 정책은 `H=0.75`, `p=3`, probability tolerance `τ=0`이며, 현재 min-E[f]와 phase2
fallback 모두 같은 수급 비용 파라미터를 사용한다. H/p 공동 최적화 연구 결과는
[`min-ef-hp-study-findings.ko.md`](./min-ef-hp-study-findings.ko.md)에 기록한다.
