# 통계 구간 모델 및 D1 rollup 검토

검토일: 2026-08-09

## 결론

- `[확인]` 현재 Wilson 구간은 유지한다. 실제 운영 집계에서 이질적 Bernoulli score 판정과 비교했을 때 키트 3개, 구간 6개, 전체 집계의 판정이 모두 같았다.
- `[확인]` 현재 Wilson 범위의 표준오차 폭 추정치는 시도별 확률 차이를 반영한 값보다 약 3%~12% 넓다. 따라서 현 데이터에서는 더 복잡한 모델보다 보수적으로 작동한다.
- `[확인]` D1 rollup table은 도입하지 않는다. 현재 전체 통계 쿼리의 저장 행과 지연은 materialized rollup의 쓰기·migration·운영 비용을 정당화하지 못한다.
- `[추론]` 새로운 데이터 규모나 판정 불일치가 확인되기 전에는 통계 구간 수식과 D1 스키마를 늘리지 않는 편이 위험 대비 효용이 높다.

## 구간 모델 검증

현재 UI는 관측 성공률에 Wilson 95% 구간을 적용하고, 등급·레벨·키트별 시도 수로 가중한 이론 확률과 비교한다. 운영 데이터의 61개 `grade/level/kit` 집계로 다음 두 판정을 비교했다.

1. 현재 Wilson 구간과 가중 이론 확률
2. 시도별 확률에 따른 `sum(p_i(1-p_i))` 분산을 사용한 이질적 score 판정

9개 표시 단위와 전체 합계까지 10개 검토 단위에서 판정 변경은 0건이었다. 현재 Wilson 폭에 대응하는 표준오차 추정치는 이질적 분산 기준보다 약 1.03~1.12배 넓었다.

```text
sum p_i(1-p_i)
= N * p_bar * (1 - p_bar) - N * Var(p_i)
<= N * p_bar * (1 - p_bar)
```

즉 확률이 서로 다른 시도를 같은 평균 확률의 binomial로 단순화하면 분산을 줄이는 대신 키우게 된다. 현재 UI 범위는 이 차이를 이용해 판정을 공격적으로 좁히지 않는 보수적 표시다.

추천 실행은 실패로 레벨이 바뀌는 즉시 종료되므로 한 이벤트에 기록된 모든 실제 시도는 같은 시작 레벨 확률을 갖는다. D1의 1,134개 고유 이벤트 서명을 재생한 결과 이 조건을 어긴 기존 행은 0개였다. Worker validation도 앞으로 이 계약을 강제한다.

`95%`는 독립 사용자 표본이나 실제 사용자 모집단을 뜻하지 않는다. 집계된 시도 수에 따른 관측률 불확실성을 이해하기 위한 보수적 참고 범위다.

## D1 쿼리 검증

운영 `/api/stats`의 주 쿼리와 같은 SQL을 9회 순차 실행했다.

| 항목 | 값 |
|---|---:|
| 반환 그룹 | 61 |
| 주 쿼리 rows-read | 5,634 |
| 당일 쿼리 rows-read | 13 |
| 합계 rows-read | 5,647 |
| 주 쿼리 SQL p50 | 2.9613 ms |
| 주 쿼리 SQL p95 | 3.6620 ms |

응답에는 60초 CDN cache와 ETag가 적용돼 있다. 반환 그룹 수도 최대 `2 grades × 15 levels × 3 kits = 90`으로 제한된다. 현재 병목은 아니다.

rollup 검토는 다음 중 하나가 실제 관측될 때 다시 연다.

- 7일 연속 `stats_query_completed.rowsRead >= 50,000`
- 7일 rolling p95 `stats_query_completed.durationMs >= 25ms`
- 통계 API의 사용자 체감 지연 또는 D1 비용이 실제 운영 문제로 확인됨

이 기준은 현재 대비 약 7~9배의 여유를 둔다. 트래픽 성장률이 달라질 수 있으므로 도달 시점은 예측값이 아니라 관측 로그로 판단한다.
